\section{Experimental Setup}
\label{sec:setup}
\subsection{Dataset and training}
We use the KITTI object detection data~\cite{geiger2012kitti}, with 3,712 training and 3,769 validation frames. The stored frame lists are disjoint. Experiments cover Car, Pedestrian, and Cyclist. Validation supplies both checkpoint selection and the reported measurements; no hidden KITTI test result is claimed. The factorial and attention BEV comparisons complete 50 epochs using seed 42, batch size 16, BF16 training, AdamW~\cite{loshchilov2019adamw}, learning rate $7\times10^{-4}$, weight decay $10^{-3}$, four warmup epochs, and a cosine schedule to $10^{-6}$. The matched OGA--Q-OGA pair completes 100 epochs with eight warmup epochs and otherwise the same optimization settings. This pair uses focal context, SimAM, and independent grouped heads without IQA; the supplied configurations differ only in \texttt{loss.name}. AP is measured every ten epochs, and the highest Moderate macro-average determines the primary checkpoint. Final3D also completes 100 epochs with eight warmup epochs, but is selected by reference 3D AP. Two older backbone runs have different budgets and loss-based selection; their scores are retained only as historical context.

The main configurations use ground-truth object sampling with probability 0.5, source-relative placement, range scaling from 0.9 to 1.1, and azimuth jitter of $\pm5^\circ$. Whole-scene quotas are 15 Cars, 10 Pedestrians, and 10 Cyclists; these are target counts, rather than a fixed number of insertions. Density adaptation, ground checks, static collision rejection, and visibility protection are enabled. Subsequent transformations apply a random flip, rotation in $[-\pi/4,\pi/4]$, scale in $[0.95,1.05]$, and probabilistic translation with standard deviations $(0.2,0.2,0.1)$ m. The configured object database is derived from training data. Saved configurations and their training-time hashes accompany the manuscript.

\subsection{Evaluation protocols}
\label{sec:protocols}
The BEV ablations use a local loader-aligned implementation of KITTI-style rotated AP with 40 recall positions (R40). It evaluates the loader's strictly cropped horizontal center domain, difficulty filters, and configured neighboring-class ignores. Car uses IoU 0.7 and Pedestrian/Cyclist use 0.5. Moderate mAP is the unweighted mean of the three class AP values, reported as a percentage. This local evaluation supports internal comparisons, but it does not establish equivalence to a full-frame reference result.

Final3D uses the unchanged KITTI evaluation and rotated-overlap code from a pinned OpenPCDet revision~\cite{openpcdet}. It evaluates full-frame original annotations, with calibrated, image-clipped projections of predicted cuboids. BEV and 3D AP use the same thresholds and R40 convention. The input crop remains the detector's sensing domain, while ground truth follows the reference evaluator's full-frame domain. We report these scores separately from the local BEV study. The evaluator revision, source hashes, split digest, and checkpoint digest are supplied in Supplementary Note~S3.

\subsection{Efficiency and conditional diagnostics}
Saved BEV runtime measurements use PyTorch FP32 on an NVIDIA L4. Model forward time and the offline input-to-detections time are reported separately, including loading/encoding, host-to-device transfer, and decoding/suppression. Measurements exclude ten warmup frames and cover 3,759 timed frames. Parameter counts include the detector and exclude train-only adaptive criterion parameters. The Final3D evaluation does not contain stage-level latency measurements, so the BEV timings are not assigned to it.

Existing CPU diagnostics for the selected Final3D checkpoint form one-to-one, same-class associations in descending BEV IoU, using Moderate ground-truth filters and projected detection height of at least 25 pixels. At fixed associations, footprints, scores, and original image boxes, an oracle replaces the camera-coordinate vertical bottom location and/or height. The diagnostic counts 3D IoU threshold crossings. It does not reproduce neighboring-class ignores, DontCare handling, or AP matching, and therefore does not measure oracle AP. Its CPU detections also differ slightly from the saved GPU reference detections.
