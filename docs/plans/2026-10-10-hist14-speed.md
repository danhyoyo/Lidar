# Hist14 CPU and input-layout optimization

### Goal
Reduce hist14 rasterization and model-input preparation latency while retaining
hist14 v1 semantics and existing checkpoint/config identities.

### Constraints
- Keep float64 geometry/statistics, float32 output, ROI/bin boundary behavior,
  explicit NumPy/Numba selection, and the public contiguous HWC encoding API.
- Give datasets contiguous CHW input without copying a dense HWC image.
- Own each returned array independently; support workers, concurrent calls,
  arbitrary numeric/noncontiguous input, empty clouds, and custom geometry.

### Known context
Numba currently allocates a dense 14-column float64 accumulator, traverses all
grid cells, and emits HWC. Dataset permute plus evaluator contiguous adds a copy.
Real KITTI clouds are available in Kitti_Raw/velodyne/training/velodyne.
The installed AI_env has NumPy, Numba, and PyTorch; CUDA is unavailable.

### Risks
Boundary or variance rounding changes, stale buffers, modified public layout,
misleading CPU-only performance claims, and regressions on dense/custom grids.

### Options
1. Layout-only fix: low risk, removes model-input copy, leaves kernel overhead.
2. Compact occupied-cell accumulation plus direct CHW output: removes dense
   workspace, empty-cell normalization, and input copy; preserve arithmetic.
3. Float32/fastmath or GPU rasterization: potentially faster, but changes numeric
   behavior or adds a deployment dependency without available GPU verification.

### Recommendation
Option 2, with a compact density lookup for repeated integer counts and measured
incremental experiments. Keep NumPy as the independent semantic reference.

### Acceptance criteria
- HWC and CHW agree with the NumPy reference at existing tolerances; the NumPy
  path itself remains bitwise equivalent to the original.
- Compiled outputs agree bitwise with the original compiled backend on sampled
  real KITTI clouds, or any deviation is explained and bounded before acceptance.
- Dataset hist14 tensors are contiguous; successive/concurrent calls do not
  mutate previously returned arrays.
- Matched warmed CPU rasterization plus CHW preparation is materially faster on
  multiple real frames; report first-call/JIT separately and make no new GPU/AP claim.

### Assumptions
Optimize CPU preparation within the current deployment contract. Preserve the
configured backend rather than silently substituting a dependency. No training,
checkpoint rewrite, or architecture change is required.

### Risks & mitigations
Use no shared mutable output/workspace; leave semantic metadata unchanged;
test ROI/bin ties, constant heights, integer/strided inputs, concurrent calls,
and real frames. Avoid timing thresholds in automated tests.

### Rollback plan
Revert only hist14 backend, dataset branch, benchmark and their tests/docs.
Existing model/config/checkpoint identities stay usable in either implementation.

### Results
- Implemented occupied-cell NumPy/Numba statistics, direct dataset CHW output,
  native floating input reads, small-count density reuse, and explicit Numba
  defaults in eleven experiment configs, manifest, and both notebooks.
- Public HWC remains contiguous; semantic version/hash remains unchanged.
- Follow-up audit verifies the original snapshot against Git HEAD and checks
  float32 uint32 bit patterns on 100 real KITTI frames plus seven synthetic
  clouds: zero mismatches in all 14 channels, both backends and layouts.
  Randomized interleaved Numba CPU input preparation across three frames:
  47.23 -> 4.97 ms at one thread, 40.39 -> 4.61 ms at six threads (8.76–9.50x).
  The initial separate-block 24.05x result is retained as historical evidence,
  not a general speedup claim; allocator/cache state materially affects timing.
- CUDA is accessible outside the sandbox. The existing trained R8 checkpoint on
  RTX 4050, FP32, five real frames: encoding + H2D + forward + decode/NMS
  initial separate-block timing 62.60 -> 14.46 ms; detections are numerically
  identical. Excludes file I/O and AP; GPU timing has not been re-audited with
  randomized interleaving.
- Focused verification: 99 encoding/schema/notebook tests, 81 checkpoint tests,
  37 grouped pipeline tests including real workers, and 64 unified workflow tests
  pass; three optional reference tests skip in the sandbox.
- Baseline archive of HEAD reproduces fourteen existing preset/smoke/notebook
  failures. The two reference CUDA evaluator failures reproduce on HEAD outside
  the sandbox and require unavailable Numba CUDA/libNVVM/libdevice dependencies.
- Review found no new correctness or ownership issue; fastmath is disabled,
  returned storage is per-call, and arbitrary input promotion/boundaries retain
  the previous contract. User-owned diagrams and unrelated edits are preserved.
- Final full suite: 1,754 passed, 19 skipped, 18 failed (fourteen reproduced
  preexisting failures, four reference CUDA dependency failures), 15 subtests
  passed. Socket transport passes outside sandbox; temporary fixtures were moved
  to disk after the initial full suite exhausted the /tmp quota.
- Performance details and reproducible commands: docs/hist14_performance.md.
