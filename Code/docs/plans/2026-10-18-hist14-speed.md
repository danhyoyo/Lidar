# Hist14 revision 3 performance work

### Goal
Reduce warmed Hist14 CPU preparation time and measure it against Binary35 on
identical real KITTI frames, retaining Hist14 v1 checkpoint compatibility.

### Constraints
Keep float64 arithmetic/order, float32 features, ROI/bin rules, all 14 channels,
independent result ownership, both public layouts, and explicit backend choice.

### Known context
Revision 2 already uses compact occupied-cell statistics and direct CHW output.
Its final row-first scatter touches 14 widely separated planes per occupied cell.
Real KITTI clouds and a NumPy/Numba environment are available locally.

### Risks
Layout changes can alter feature order or rounding; allocation and cache effects
can distort comparisons. Local CPU measurements do not replace archived T4/L4
pipeline measurements or establish AP.

### Options
1. Improve locality of CHW output and eliminate repeated divisions where exact:
   small scope, no new runtime dependency, bitwise parity required.
2. Parallelize accumulation: contention/order changes and thread oversubscription
   make exact parity and worker deployment harder.
3. GPU rasterization: changes deployment and requires a separate numeric audit.

### Recommendation
Measure option 1 first, accept only measured improvements with exact parity.
Keep the NumPy reference independent.

### Acceptance criteria
- Zero uint32 output mismatches against revision 2 on sampled real and edge cases.
- Existing encoding, dataset, augmentation and schema tests pass.
- Randomized, interleaved matched timings include Binary35 rasterization and
  contiguous CHW preparation; retain raw samples and first-call timings.
- Describe local hardware/scope and limits explicitly; no new AP claim.

### Assumptions
No retraining, architecture, feature removal, precision reduction, or checkpoint
rewrite is needed. Preserve unrelated workspace edits and historical results.

### Plan
1. Capture baseline, profile candidate output layouts on real clouds.
   - Files: ignored `artifacts/hist14_speed_v3/`.
   - Verify: warmed randomized timings and original source SHA-256.
2. Add parity regressions, then implement the measured layout change.
   - Files: `tests/test_hist14_backend.py`,
     `detector/core/datasets/utils_1/bev_backend.py`.
   - Verify: old/new uint32 parity and focused pytest suites.
3. Publish a reproducible interleaved comparison with Binary35.
   - Files: `tools/benchmarks/benchmark_bev_encodings.py`, benchmark tests,
     `docs/hist14_performance.md`.
   - Verify: CLI tests, real-frame audit, relevant integration tests, diff check.

### Risks & mitigations
Use no global mutable buffers or fastmath, keep scratch per call, compare both
layouts and multiple input dtypes, and exclude JIT from steady state.

### Rollback plan
Revert only this change's backend, benchmark, tests, and documentation changes.
The ignored source snapshot records the starting revision independently.

### Results
- Kept early per-axis ROI rejection, removed redundant coordinate finite checks,
  and retained the original float64 statistic expressions and output ownership.
- Rejected scatter reordering, padded accumulators and literal-dispatch prototypes
  after measuring insufficient or negative benefits. No candidate buffer/layout
  changes were retained in production.
- Original revision-2 snapshot matches HEAD byte-for-byte. On 12 matched frames,
  warmed interleaved CHW means were 3.085 ms before and 3.013 ms after (2.34%
  lower latency). Native rasterization was 2.693 ms for Hist14 vs 6.662 ms for
  the existing Binary35 implementation. Binary35 contiguous CHW was 102.296 ms.
- Both layouts match revision 2 bit-for-bit on 100 real validation frames and
  eight edge cases. Focused encoding/benchmark/schema/integration/checkpoint
  verification passed 177 tests. No training or AP evaluation was run.
- Published timing/parity/source evidence in Result/hist14_speed_20261018;
  previous T4/L4 tables remain unchanged because they require GPU remeasurement.
